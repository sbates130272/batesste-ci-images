# cloud-init packages for the "ionic" guest flavour: the verbs userspace, and
# everything needed to build rdma-core from source and the ionic-ernic DKMS
# modules against the guest kernel.  The modules themselves are not built here -- building them is what
# the consuming jobs exist to test.
#
# Nothing here may be kernel-versioned: cloud-init runs before the mainline
# kernel is installed, and ${KERNEL_VERSION} would expand to the *host* kernel
# in any case.
build-essential
cmake
ninja-build
pkg-config
dkms
git
# No linux-headers-generic and no linux-modules-extra.  This flavour boots a
# mainline kernel (kernel_ref in images.yml), not the 7.0 the release ships, so
# the -generic metapackages would pull headers DKMS must not build against.
# The matching linux-headers-<ver>-generic comes with the mainline .debs, as
# does linux-modules-<ver>-generic, which carries ib_core, ib_uverbs, rdma_ucm
# and both halves of ionic -- the RDMA stack this flavour exists for is
# therefore present at first boot with nothing extra to install.
#
# Dependencies of those .debs, pre-seeded so the kernel install is a local
# dpkg operation rather than a second round of archive resolution.
linux-base
kmod
initramfs-tools
wireless-regdb

# rdma-core build dependencies (upstream v62 wants all of these).
libnl-3-dev
libnl-route-3-dev
libudev-dev
libsystemd-dev
python3-docutils

# Distro rdma-core, which on resolute is 61.0 -- past the v61 that first
# shipped providers/ionic upstream, so ibverbs-providers carries
# libionic-rdmav59.so and nothing has to be built to get it.  That is the
# provider the whole flavour turns on, as well as ibv_devinfo and friends.
# The build deps above stay listed even so: the consuming jobs build rdma-core
# themselves whenever their pin moves past what the release packages, or when
# they need the GDA patches.
rdma-core
ibverbs-utils
libibverbs-dev

# ib_send_bw and friends, for jobs that want to move traffic over the ionic
# queue pairs rather than only assert the modules built.  The distro build
# links libibverbs.so.1 and loads providers at runtime, so it picks up libionic
# with nothing done to it -- including a source rdma-core a consuming job
# installs over the top.
# It is built without ROCm or CUDA memory support, though: --use_rocm needs
# perftest compiled against a ROCm the guest does not carry.
perftest

pipx
python3-venv
